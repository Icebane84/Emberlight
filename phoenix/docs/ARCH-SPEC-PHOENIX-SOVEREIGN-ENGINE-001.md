## [SEC-01] Executive Summary & Zero-Dollar Sovereign Philosophy

`ARCH-SPEC-PHOENIX-SOVEREIGN-ENGINE-001` formalizes the architecture of the **Phoenix Sovereign Engine & Governance Substrate**, enabling an air-gapped, zero-cost, in-browser AI-assisted development workstation.

The architecture enforces absolute **Zero Ambient Authority** and **Zero External Cloud Dependencies** (VSRP-001 / Faraday Isolation):

1. **Zero NPM / Zero Bundlers:** 100% vanilla ES2022+ web standards operating directly over `file://`, standalone HTML monoliths, or standard HTTP origins.
2. **Deterministic Governance Gates:** Every code modification proposed by human engineers or local AI models (via WebLLM or local Ollama) must pass a 4-tier verification pipeline before committing to the virtual or project file system.
3. **Cryptographic Receipt Ledger:** Every attempted transaction emits an immutable, FNV-1a hashed `PGE-RECEIPT-1` record logged to memory and append-only OPFS (`receipt-journal.ndjson`).
4. **Token-Efficient Repair Loop:** Behavioral and structural rejections trigger an automatic repair cycle (`repairLoop`) with AST-isolated fault slicing (`extractFaultSlice`) rather than full-file context dumps.
5. **Watchdog Execution Shield (Tier 4):** `executeWithTimeout` protects the browser UI thread against non-terminating loops and blocking operations during evaluation.
6. **Headless Framebuffer Checksums:** `validateFramebufferSignature` / `computeFramebufferHash` provide in-memory pixel validation for graphical rendering verification without external image assets.
7. **Strict Multi-Tier Partitioning (MPFS-001):** High-velocity navigation via standardized `#region` folding, `CMD-DOC-INDEX` anchors, and downward-only dependency flow per `PSGC-001`.

<!-- #region [SEC-02] --- 4-Gate Transaction Pipeline Topology (PGE-DSL-1) -->
## [SEC-02] 4-Gate Transaction Pipeline Topology (PGE-DSL-1)

All code change proposals flow through `Governor.submit(proposal, subject)` in `phoenix_sovereign_engine.js [ENG-14]`. The pipeline is implemented across four named gate constants (`GATES.*`) and emits a `PGE-RECEIPT-1` record after every attempt — accepted or rejected.

```plain text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                PHOENIX GOVERNOR PIPELINE                               │
│                           Governor.submit(proposal, subject)                           │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│   [Human / Local AI] ──> PGE-DSL-1 Proposal                                           │
│                                 │                                                      │
│                                 ▼                                                      │
│   ┌────────────────────────────────────────────────────────────────────────────────┐   │
│   │ GATE 1: STRUCTURAL_GATE  (GATES.STRUCTURAL / _gateStructural)                  │   │
│   │ - Shape validation: schemaVersion == "PGE-DSL-1", required fields present      │   │
│   │ - Target registration check: proposal.target must be in SpecificationRegistry  │   │
│   │ - Operation allowlist: proposal.operation in target.allowedOperations          │   │
│   │ - Hot-loop violation scan: _checkHotLoopViolations (new Array, new Object...) │   │
│   │ - On failure: Receipt emitted to journal; proposal DISCARDED (no state change) │   │
│   └──────────────────────────────────────┬─────────────────────────────────────────┘   │
│                                          │ [PASS] → lifecycle = TRANSACTION            │
│                                          ▼                                             │
│   ┌────────────────────────────────────────────────────────────────────────────────┐   │
│   │ GATE 2: CAPABILITY_GATE  (GATES.CAPABILITY / CapabilityRegistry)               │   │
│   │ - Subject token verification via governor.grant(subject, target, op, txId)     │   │
│   │ - Operation permissions checked against CapabilityRegistry per target          │   │
│   │ - Monotonic tick expiry: DEFAULT_CAP_EXPIRY = 16 ticks                         │   │
│   │ - On failure: caps.clearTransaction(txId); lifecycle = READY; DISCARDED        │   │
│   └──────────────────────────────────────┬─────────────────────────────────────────┘   │
│                                          │ [PASS]                                      │
│                                          ▼                                             │
│   ┌────────────────────────────────────────────────────────────────────────────────┐   │
│   │ GATE 3: BEHAVIOR_GATE  (GATES.BEHAVIOR / _gateBehavior)                        │   │
│   │ - Changes applied speculatively to in-memory sources (_applyChanges)           │   │
│   │ - Spec invariants evaluated (SpecificationRegistry.invariants)                 │   │
│   │ - Test suite evaluated under executeWithTimeout watchdog                       │   │
│   │ - On failure: _rollback(before) restores sources to pre-transaction snapshot   │   │
│   └──────────────────────────────────────┬─────────────────────────────────────────┘   │
│                                          │ [PASS]                                      │
│                                          ▼                                             │
│   ┌────────────────────────────────────────────────────────────────────────────────┐   │
│   │ GATE 4: EXECUTION & COMMIT  (GATES.ALL / GATES.EXECUTION)                      │   │
│   │ - Sources committed; lifecycle = READY                                         │   │
│   │ - FNV-1a PGE-RECEIPT-1 receipt built and appended to ReceiptLedger             │   │
│   │ - Receipt serialized to OPFS journal (receipt-journal.ndjson)                  │   │
│   │ - On runtime exception: _rollback called; GATES.EXECUTION receipt emitted      │   │
│   └────────────────────────────────────────────────────────────────────────────────┘   │
│                                                                                        │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### 2.1. Automatic AI Repair Loop (`repairLoop`)

When `BEHAVIOR_GATE` rejects a proposal, `Governor.repairLoop(receipt, originalProposal, subject, llmBridge, proposalParser)` invokes the local LLM (Ollama or WebLLM) up to `REPAIR_LOOP_CAP = 3` times. Each iteration feeds only the fault-sliced context (`extractFaultSlice`) — not the full file — capping repair prompts at $< 300$ tokens.
