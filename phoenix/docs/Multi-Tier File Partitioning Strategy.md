## [SEC-01] Executive Summary & Core Premise

In a zero-dependency, zero-bundler vanilla JavaScript architecture (operating natively over `file:///` or standard HTTP without npm packages, Webpack, or Babel), development teams face two opposing architectural hazards:

1. **The Fragmentation Trap:** Splitting code prematurely into hundreds of tiny files creates dependency-order fragility, script-tag waterfalls, path resolution bugs, and cognitive navigation fatigue.
2. **The Monolith Trap:** Keeping 3,000+ lines in a single unstructured file risks invisible coupling, accidental variable shadowing, global scope leakage, and unmanageable cognitive overhead.

### Monolithic Modularity: Partitioning Without Fragmentation

You **can** achieve full modular separation of concerns inside a single-file monolith. In fact, that is the exact design philosophy behind **MPFS-001 (Multi-Tier File Partitioning Standard)** and our Sovereign Cartridge architecture (**`PSGC-001`**). Nothing technical stops you from running a strictly partitioned, decoupled architecture entirely within a single `.html` or `.js` file.

The **Multi-Tier File Partitioning Strategy (MPFS-001)** bridges this divide. Codified under **`PSGC-001 [SEC-01.2]`**, it provides a universal, language-native structural methodology combining:

### Pure Function Contracts (Zero-Closure Leakage)

```javascript
//#region [SEC-04] DAMAGE FORMULAS & AFFINITY ENGINE

/**
 * Pure calculation helper.
 * Zero external closure reads. Ready for instant extraction into a separate file.
 *
 * @param {BattlerUnit} attacker Striking entity
 * @param {BattlerUnit} target Receiving entity
 * @param {number} [skillPower=1.0] Skill potency multiplier
 * @param {number} [randomFloat=0.5] Seeded stochastic variation in [0, 1)
 * @returns {StrikeCalculationResult}
 */
function calculateStrikeDamage(attacker, target, skillPower = 1.0, randomFloat = 0.5) {
    if (!attacker || !target) {
        return { damage: 0, isCrit: false, affinity: 'NEUTRAL' };
    }

    const variance = (randomFloat * 0.1) - 0.05; // +/- 5%
    const isCrit = randomFloat < 0.10;
    const rawDamage = Math.max(1, (attacker.atk * 2) - target.def);
    const finalDamage = Math.floor(rawDamage * skillPower * (isCrit ? 1.5 : 1.0) * (1 + variance));

    return {
        damage: Math.max(1, finalDamage),
        isCrit,
        affinity: 'NEUTRAL'
    };
}

//#endregion
```

## [SEC-05] Structural Layer 4: Namespace Sub-Object Partitioning & Immutable Subsystems

Instead of scattering helper functions and state variables across the global or closure scope, group related logic into immutable namespace objects inside your cartridge closure.

### Subsystem Namespace Pattern

```javascript
//#region [SEC-05] SUBSYSTEM NAMESPACE PARTITIONING

/**
 * Cohesive Physics Kernel namespace.
 * Encapsulates integration calculus and collision manifolds without external closure bleed.
 */
const PhysicsKernel = Object.freeze({
    /**
     * Integrates position from velocity over delta time.
     * @param {number} px
     * @param {number} py
     * @param {number} pvx
     * @param {number} pvy
     * @param {number} dt
     * @returns {{ px: number, py: number }}
     */
    integrateVelocity(px, py, pvx, pvy, dt) {
        return { px: px + pvx * dt, py: py + pvy * dt };
    },

    /**
     * Evaluates geometric collision between two entities.
     * @param {BattlerUnit} entityA
     * @param {BattlerUnit} entityB
     * @returns {boolean}
     */
    resolveCollisions(entityA, entityB) {
        return Math.hypot(entityA.x - entityB.x, entityA.y - entityB.y) < 16;
    }
});

/**
 * Cohesive Render Subsystem namespace.
 * Manages frame draw quads and shader uniforms.
 */
const RenderSubsystem = Object.freeze({
    /**
     * Encapsulates vertex batch pushing.
     * @param {WebGLRenderingContext} gl
     * @param {Float32Array} quadBuffer
     */
    pushSpriteQuad(gl, quadBuffer) {
        // Buffer push logic
    },

    /**
     * Dispatches active uniforms to the GPU pipeline.
     * @param {WebGLRenderingContext} gl
     * @param {WebGLProgram} program
     */
    dispatchUniforms(gl, program) {
        // Uniform dispatch logic
    }
});
```

//#endregion

### Why Namespace Partitioning Works

1. **Strict Functional Boundaries:** `PhysicsKernel` cannot arbitrarily mutate rendering buffers unless explicitly passed, preventing invisible coupling and state corruption.
2. **Zero-Surgery Extraction:** Because each subsystem is already self-contained inside a discrete namespace object, extracting it into an independent physical file (`physics_kernel.js`) requires zero refactoring at consumption sites.
3. **Runtime Inviolability (`Object.freeze`):** Freezing namespace objects guarantees that runtime execution, tenant extensions, or dynamic scripts cannot monkey-patch or overwrite core subsystem methods.
4. **Static Type Parity:** When combined with JSDoc annotations, your IDE (`checkJs: true`) provides autocomplete, type safety, and symbol renaming across internal partitions identically to imported TypeScript modules.

## [SEC-06] Structural Layer 5: MPFS-001 Multi-File Extraction & Staging

When a domain grows so large that it must be split across physical files, use the **Staging Membrane & Root Facade Sealing Pattern** codified in **`PSGC-001 [SEC-02.4]`**. This prevents script-tag waterfalls from polluting the global `window` scope with loose functions.

```plaintext
┌────────────────────────────────────────────────────────┐
│ 1. Sub-Modules populate private staging membrane:      │
│    window._CombatInternal.calc = calculateDamage;      │
│    window._CombatInternal.queue = processTurnQueue;    │
└───────────────────────────┬────────────────────────────┘
                            │ (Executed in topological load order)
                            ▼
┌────────────────────────────────────────────────────────┐
│ 2. Root Facade (combat.js) ingests membrane:           │
│    - Assembles public API singleton                    │
│    - Calls Object.freeze(EmberlightCombat)             │
│    - Purges staging object: delete window._Combat*     │
└────────────────────────────────────────────────────────┘
```

### Sub-Module Example (`combat/combat_calc.js`)

```javascript
(function () {
    'use strict';
    const _membrane = window._CombatInternal = window._CombatInternal || {};

    function calculateDamage(attacker, target) {
        return Math.max(1, (attacker.atk * 2) - target.def);
    }

    _membrane.calculateDamage = calculateDamage;
})();
```

### Root Facade Sealing Example (`combat.js`)

```javascript
const EmberlightCombat = (function () {
    'use strict';
    const _sub = window._CombatInternal || {};

    const publicApi = {
        calculateDamage: _sub.calculateDamage || ((a, b) => 0),
        version: '1.0.0'

    // Seal API singleton to prevent runtime monkey-patching
    Object.freeze(publicApi);

    // Purge the temporary staging membrane completely (INV-07 Faraday Boundary)
    if (typeof window !== 'undefined') {
        delete window._CombatInternal;
    }

    return publicApi;
})();

if (typeof window !== 'undefined') window.EmberlightCombat = EmberlightCombat;
if (typeof module !== 'undefined') module.exports = EmberlightCombat;
```

### WASM SIMD Boot Pattern (`CAP_WASM_SIMD`)

At CSOC Phase 3, Plane 2 (Coordinator) reads the `[WASM-XX]` socket and instantiates the binary with zero network requests:

```javascript
//#region [WASM-01] ZERO-FETCH WASM SIMD KERNEL INSTANTIATION

/**
 * Decodes and instantiates the inlined Base64 WebAssembly SIMD kernel.
 * Capability guard: aborts gracefully if WebAssembly is unavailable.
 * @returns {Promise<WebAssembly.Instance | null>}
 */
async function _bootWasmSIMDKernel() {
    if (typeof WebAssembly === 'undefined') return null; // CAP_WASM_SIMD guard

    const socketEl = document.getElementById('wasm-simd-kernel');
    if (!socketEl) return null;

    // Decode Base64 text content to binary buffer
    const b64 = socketEl.textContent.trim();
    const binStr = atob(b64);
    const bytes = new Uint8Array(binStr.length);
    for (let i = 0; i < binStr.length; i++) bytes[i] = binStr.charCodeAt(i);

    const { instance } = await WebAssembly.instantiate(bytes.buffer, {});
    return instance;
}

//#endregion
```

### WGSL / WebGPU Compute Pattern (`CAP_WEBGPU_ACCEL`)

> [!WARNING]
> `CAP_WEBGPU_ACCEL` requires Chrome 113+ and a secure context (`https://` or `localhost`). Always wrap in a capability guard and fall back to Canvas2D rendering under `CAP_CANVAS2D`. Running under `file:///` without a server **does not** satisfy the secure context requirement for WebGPU.

```javascript
//#region [WGSL-01] NATIVE WGSL COMPUTE PIPELINE BOOT

/**
 * Reads the [WGSL-01] socket and creates a GPU shader module.
 * Capability guard: returns null if navigator.gpu is unavailable.
 * @param {GPUDevice} device - Active WebGPU logical device
 * @returns {GPUShaderModule | null}

function _buildWGSLComputeModule(device) {
    if (typeof navigator === 'undefined' || !navigator.gpu) return null; // CAP_WEBGPU_ACCEL guard

    const socketEl = document.getElementById('wgsl-compute-pass');
    if (!socketEl) return null;

    return device.createShaderModule({ code: socketEl.textContent });
}

//#endregion
```

### SDCP-001 Capability Attenuation Contract

Polyglot sockets obey `SDCP-001` Zero Ambient Authority:

- Plane 1 (Worker Kernel) **must not** access `document.getElementById`. Socket content must be extracted by Plane 2 (Coordinator) and passed to Plane 1 as a `Transferable` (e.g., `ArrayBuffer` for WASM, plain string for WGSL) via a `PMIP-001` capability envelope.
- Socket IDs are treated as **capability handles** — Plane 1 receives only the decoded payload, never the raw DOM reference.

### CSP & Deployment Notes

> [!CAUTION]
> Inlining Base64 WASM inside `<script type="text/plain">` is **compatible with** `script-src 'self'` CSP policies because the socket is not an executable script tag. However, `WebAssembly.instantiate()` from an inline buffer requires `'unsafe-eval'` or `'wasm-unsafe-eval'` in the `script-src` directive on locked-down deployments. Document this trade-off for any cartridge targeting a hardened CSP environment.

## [SEC-06C] Structural Layer 5.6: SharedArrayBuffer Multi-Plane Topology

**Governing Standards:** `CAP_SHARED_MEM` / `SDCP-001` / `PMIP-001` / `PERSIST-001` / `MPFS-001`

### Heap Allocation Pattern

```javascript
//#region [SEC-06C] SHARED MEMORY HEAP ALLOCATION & ATOMIC CONTROL

/**
 * Allocates the PERSIST-001 heap over a SharedArrayBuffer for zero-copy cross-plane access.
 * Must be called in Plane 2 (Coordinator) and transferred to Plane 1 via postMessage.
 * Capability guard: falls back to standard ArrayBuffer if SharedArrayBuffer is unavailable.
 * @returns {{ heap: SharedArrayBuffer | ArrayBuffer; isShared: boolean }}
 */
function _allocateSovereignHeap() {
    if (typeof SharedArrayBuffer !== 'undefined') {
        const sab = new SharedArrayBuffer(2048); // CAP_SHARED_MEM active
        return { heap: sab, isShared: true };
    }
    return { heap: new ArrayBuffer(2048), isShared: false }; // Graceful fallback
}

/**
 * Notifies the Worker kernel that new input has been committed to the shared ring buffer.
 * Main thread uses Atomics.notify() — Atomics.wait() is PROHIBITED on the main thread.
 * @param {Int32Array} controlView - Int32Array over the SharedArrayBuffer control region
 */
function _notifyWorkerInputReady(controlView) {
    Atomics.store(controlView, 0x01C >>> 2, 1);  // Set input-ready flag at 0x01C
    Atomics.notify(controlView, 0x01C >>> 2, 1); // Wake exactly 1 waiting Worker
}

//#endregion
```

### Atomics Asymmetry Rule (`INV-SAB-01`)

> [!IMPORTANT]
> **`Atomics.wait()` is prohibited on the main thread** (Plane 0 / Plane 2). Calling it blocks the UI event loop and triggers a browser exception. Only Plane 1 (Dedicated Worker) may call `Atomics.wait()`. Plane 0 / Plane 2 must use `Atomics.notify()` exclusively. Violating this invariant causes `ERR_0x1F: MAIN_THREAD_ATOMIC_WAIT_VIOLATION`.

### Staging Membrane Interaction

When `CAP_SHARED_MEM` is active, the staging membrane from `[SEC-06]` is extended: the `SharedArrayBuffer` handle is passed as a `Transferable` item in the Blob spawner message (not via `window._staging`), because Workers cannot access `window`. The PMIP-001 capability envelope carries `{ type: 'INIT_HEAP', heap: sab }` as the first Plane 2 → Plane 1 message.

### The Trade-Off Matrix: Monolithic Modularity vs. Multi-File Workspace

| Architectural Dimension      | Single-File Monolithic Modularity (`MPFS-001`)                                                                                                                                                                                                 | Multi-File Workspace (`Vite / ES Modules`)                                                                                                                 |
| :--------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Deployment Friction**      | **Zero.** Double-click the `.html` file; it runs instantly anywhere (`file:///`). Zero npm install, zero build step.                                                                                                                           | Requires a local dev server (`npm run dev`) or a static build step due to browser CORS policies on `file:///`.                                             |
| **Portability & Archival**   | **Pristine.** Perfect for cartridges, game jams, embedded toolchains, and offline sandboxes. Single atomic payload.                                                                                                                            | Requires folder zipping, dependency lockfiles, package manifests, and path resolver configuration.                                                         |
| **Git Version Control**      | **Challenging.** Concurrent edits by multiple developers to the same file cause merge conflicts in busy regions.                                                                                                                               | **Superior.** Clean pull requests, granular per-file diffs, and independent file ownership across teams.                                                   |
| **Scope Isolation**          | Enforced structurally via closures, IIFEs, JSDoc contracts, and frozen namespace sub-objects.                                                                                                                                                  | Enforced natively by browser ESM import/export module boundaries.                                                                                          |
| **Build Tool Overhead**      | **None.** Raw browser-native execution. Instant refresh loop.                                                                                                                                                                                  | High. Toolchain updates, bundler configs, TypeScript compilation pipelines, and `node_modules` bloat.                                                      |
| **Binary Asset Embedding**   | **Native via `[SEC-06B]` Polyglot Sockets.** Base64 WASM SIMD and WGSL shaders inline in `<script type="text/plain">` sockets. Zero `.wasm` / `.wgsl` file requests. CSP requires `'wasm-unsafe-eval'` when using `WebAssembly.instantiate()`. | Binary assets require separate files, `fetch()` calls, or bundler plugins. Not portable over `file:///` without explicit `--allow-file-access-from-files`. |
| **Threading Model**          | Single-thread monolith (default). Opt-in `[SEC-06C]` `CAP_SHARED_MEM` upgrades to zero-copy `SharedArrayBuffer` across VLT-003 planes — **sacrifices `file:///` portability** (requires COOP/COEP headers).                                    | ES Module workers use `import` syntax natively; SharedArrayBuffer is available when COOP/COEP headers are set.                                             |
| **State Integrity Auditing** | `[SEC-10]` `PhoenixSymbolIndexer` provides live in-memory region graph. SHA-256 Merkle receipts via `PERSIST-001 [SEC-04]` guarantee semantic equivalence on extraction.                                                                       | File-level diffs provide per-commit change audit; no built-in runtime state integrity guarantee.                                                           |

### Execution Directives

1. **Solo Rapid Iteration & Cartridge Production: Stay Monolithic.**
   If your workflow is solo and rapid iteration is paramount, **stay in the single-file monolith**. Lean heavily into `//#region [SEC-XX]` folding, regex jump tables, and namespace objects to maintain clean modular boundaries. You get 100% of the architectural separation with 0% of the build-tool overhead.
2. **Multi-Engineer Git Collaboration: Extract via MPFS-001 Membrane.**
   When multiple engineers are actively submitting concurrent pull requests to the same subsystem, or when a domain exceeds ~5,000 lines and is ready for independent distribution, extract the target namespace sub-object into its own file using the **Staging Membrane Pattern (`[SEC-06]`)**.
3. **Threshold for Decomposition:**
   - **< 3,000 Lines:** Keep strictly single-file. Modularity is enforced via `#region` and namespace objects.
   - **3,000 – 7,500 Lines:** Monolithic modularity remains optimal if covered by `CMD-DOC-INDEX` and pure JSDoc contracts.
   - **> 7,500 Lines:** Assess team velocity. If multi-developer git merge contention occurs, partition into sub-modules governed by a central facade.

## [SEC-09] Operational Directives for AI Agents & Sovereign Governance

When an autonomous AI agent inspects, modifies, or refactors a file governed by this standard:

1. **Locate via Jump Anchor:** Always search for the section tag (`[SEC-XX]`) rather than reading the entire file sequentially. Prefer querying the `PhoenixSymbolIndexer` API (`[SEC-10]`) over sequential file reads when the symbol index is available.
2. **Preserve Section Demarcations:** Edits must remain strictly enclosed between `//#region [SEC-XX]` and `//#endregion` (or `<!-- #region [SEC-XX] -->` in HTML/Markdown).
3. **Downward Dependency Invariant (`PSGC-001 [SEC-01.2]` Rule 5):** `[SEC-N]` may only reference `[SEC-M]` where $M < N$. Circular cross-section calls are strictly forbidden.
4. **Namespace Cohesion:** When introducing a new cohesive capability, encapsulate it within a frozen namespace sub-object rather than adding standalone functions to the global closure.
5. **Pure Function Signatures:** Never access or mutate outer closure variables from inside a calculation helper. Pass all dependencies as explicit parameters.
6. **Cognitive Complexity Guardrail ($\le 15$ per SonarLint S3776):** If a function's complexity exceeds 15, invert control flow using early-return guard clauses and extract small, pure JSDoc-typed helpers co-located directly above the function *inside the same region*.
7. **Zero-Transient Hot-Loop Invariance (`INV-08` / `AC-08`):** Inside 60Hz hot paths (`update`, `render`, `tick`, `step`), transient object/array literals, closures, template strings, and `throw` statements are forbidden. Use in-band numerical status codes (`SOVEREIGN_STATUS`).
8. **Zero Placeholders:** Never emit `// ...` or `/* ... */` placeholder comments in replacement blocks. Always emit 100% syntactically complete code.
9. **Pre-Extraction Bus-Link Integrity Gate:** Before executing any multi-file extraction per `[SEC-06]`, invoke `_verifyBusLinkIntegrity()` to cross-reference all `emits` and `listens` channel declarations across section manifests. Any orphaned or unmapped EventBus topic **halts extraction** and must be resolved as `ERR_0x0D: ORPHANED_BUS_LINK` before proceeding. This enforces the OSLM topological DAG invariant at the file decomposition boundary.
10. **Polyglot Socket Capability Guard:** Before generating any `[WASM-XX]` or `[WGSL-XX]` socket content (`[SEC-06B]`), verify the target deployment context supports the required capability (`CAP_WASM_SIMD` / `CAP_WEBGPU_ACCEL`). Always emit a graceful fallback code path. Never assume secure context for `file:///` deployments.
11. **SharedArrayBuffer Plane Decomposition Guard:** Activating `[SEC-06C]` `CAP_SHARED_MEM` mandates `COOP`/`COEP` HTTP headers. Confirm `tools/server.js` is emitting these headers before any agent-authored code references `SharedArrayBuffer`. Violating this rule causes a silent instantiation failure that is not catchable at the `postMessage` boundary.

### AI Agent Integration Protocol

When a sovereign AI agent is asked to modify a file governed by MPFS-001:

1. **Query first, read second.** Call `PhoenixSymbolIndexer.resolve('[SEC-XX]')` to get `startLine`/`endLine` before opening the file. Read only the target slice, not the full monolith.
2. **Validate topology before writing.** Call `PhoenixSymbolIndexer.verifyDownwardDependencyInvariant()` after staging changes. A non-empty `violations[]` array is a hard block — do not commit the edit.
3. **Scaffold contracts automatically.** Use `PhoenixTypeResolver.scaffoldContractAtLine(source, lineNum)` (`[SEC-04]` extension) to generate strict JSDoc blocks from `phoenix.d.ts` instead of emitting `{any}`.
